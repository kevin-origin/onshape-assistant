Dimension textPosition coordinate system
----------------------------------------
- `textPosition` in an Onshape annotation requires a `viewId` field to be interpreted
  in view/model space (meters, same coordinate system as jsongeometry output).
  Without `viewId`, Onshape treats the coordinate as sheet space (mm from bottom-left
  of the sheet) — so a model-scale value like [0.3, 0.1, 0] appears at 0.3mm from the
  sheet edge, i.e. effectively the origin.
  Fix: always include `viewId: vid` in the textPosition object, same as edge references.

- Once viewId is set, textPosition coordinates are raw model meters matching jsongeometry.
  Text offset formula to get 5mm paper clearance outside the geometry:
    off = 5 * scaleDen / (scaleNum * 1000)   // paper_mm * (scaleDen/scaleNum) / 1000
  Height dim text (right of geometry):  [maxXval + off, midHval, 0]
  Width dim text (above geometry):       [midXval, maxHval + off, 0]
  No need to look up view.position — view-space coords are self-contained.

- chrome.runtime.reload() does not re-read files from disk for admin-console installed
  extensions. The extension reads from Chrome's internal profile copy, not the source
  directory. To deploy changes: publish a new version via publish.py.

INSTANCE QUANTITY for dissolved sub-asm parts (patterned fasteners):
  Occurrence paths share the SAME path string for all physical instances of a patterned part.
  e.g. all 11× PEM FH4-M4-15 generate paths `MonxbhEg.IyFheGYB.JHD.JHC` — NOT 11 unique paths.
  To count instances: count bodyData entries that reference a SPECIFIC full 4-segment path.
  Each physical instance contributes exactly 1 bodyData entry per face type.
  → qty = min(count of bodyData entries per unique full path) for that seg0 prefix.
  Example: JHC=11, JWK=11, JVK=22, JVC=61 → min=11 → 11 instances of PEM FH4-M4-15.
  The face types JHC and JWK reliably give 1-per-instance counts (top/bottom faces).
  JVK and JVC have multiples (cylindrical faces with many segments).

Part Detection via jsongeometry — UPDATED 2026-06-03
-----------------------------------------------------
Goal: find which parts are visible on the currently active drawing sheet.

STEP 0 — Detect the active sheet (multi-sheet drawings)
  For multi-sheet drawings, Onshape loads each sheet in its own production-drawing iframe
  but hides inactive ones by offsetting their parent div off-screen.
  Detection: from the parent frame (frameId 0), query all production-drawing iframes,
  check each iframe's parentElement style attribute:
    Active sheet:   style="top: 0px; left: 0px;"
    Inactive sheet: style="top: -10039px; left: -10039px;"
  Match the iframe index to drawFrames[] (from chrome.webNavigation.getAllFrames filtered
  by url.includes('production-drawing'|'onshape.com/editor')) — same order.
  Then read .active_sheet_label textContent from that frame.

  NOTE: Views API (/api/v6/drawings/.../views) has NO sheet field — cannot filter by sheet
  from the REST API alone. DRAWING_JSON export is the only way to get sheet→viewId mapping.

STEP 1 — Get view IDs for the active sheet from DRAWING_JSON export:
  POST /api/v6/drawings/d/{did}/w/{wid}/e/{eid}/translations {formatName:'DRAWING_JSON', storeInDocument:false}
  → poll GET /api/v6/translations/{id} until requestState==='DONE'
  → fetch GET /api/v6/documents/d/{did}/externaldata/{resultExternalDataIds[0]}
  → sheets[].{name, views[].viewId}  match by sheet name from DOM
  IMPORTANT: On large documents translation can take 40+ seconds. Split into two sw-exec.py
  calls: Call 1 starts translation + returns transId, Call 2 polls + processes.
  Relay/exec timeout bumped to 240s (was 120s) in sw-relay.py and sw-exec.py.

STEP 2 — jsongeometry → occurrence segments:
  GET /api/v6/drawings/d/{did}/w/{wid}/e/{eid}/views/{viewId}/jsongeometry
  → bodyData[].rightRepOccurrences + leftRepOccurrences = dot-separated occurrence paths
  First segment before first dot = root instance/part ID.

OCCURRENCE PATH FORMAT — two variants:
  3-segment: {rootInstanceId}.{partId}.{bodyId}
    → seg[0] = root assembly instance ID → look up in rootAssembly.instances
  4-segment: {subAsmInstanceId}.{innerInstanceId}.{partId}.{bodyId}
    → seg[0] = dissolved/deleted sub-assembly instance → NOT in rootAssembly.instances
    → seg[1] = instance that was inside that sub-asm → now at root level (same instance ID preserved)
    → resolve via seg[1] in rootAssembly.instances

  So the rule: always try seg[0] in rootAssembly.instances first; if not found AND path has ≥4 segs,
  try seg[1] in rootAssembly.instances.

  Example from doc 1eb066132dd8435f7b3666f3 / bf6fccd05228c2b5db3f62b4:
    MonxbhEgpCvz5aHjw.IyFheGYB2MAii/cGB.JHD.JHC
      → MonxbhEgpCvz5aHjw NOT in root (deleted sub-asm), IyFheGYB2MAii/cGB IS at root = PEM FH4-M4-15
    MNnpPCU4Jsf2lygyk.IAxxJAyTcdB3H1RIl.JHD.JVC
      → similar, resolves to PEM FH4-M4-8

  3-seg unknown (seg[0] not in root): seg[0] was a root instance of an external sub-assembly/PS
  that got deleted. seg[1] is a partId (short, like KF/B) — look up in asmDef.subAssemblies[].instances
  by matching inst.partId to find the component name.
  Example: Mqty53LYZ4Ow8F+MU.KFbF.{body} → KFbF is a PCB component in an external electronics asm

STEP 3 — Resolve segment IDs to part names (multi-strategy):

  Strategy A — Normal 3-seg (seg[0] in rootAssembly.instances):
    GET /api/v6/assemblies/d/{did}/w/{wid}/e/{asmEid}
    → rootAssembly.instances[].{id, name, partId, elementId, documentId, documentVersion}
    Match occ.split('.')[0] === instance.id → use instance.name.replace(/ <\d+>$/, '')
    Qty = count of same name (multiple instances of same part).

  Strategy B — 4-seg dissolved sub-asm (seg[0] NOT in root, path length ≥ 4):
    Use seg[1] as innerInstanceId → look up in rootAssembly.instances.
    When a sub-assembly is dissolved (parts moved to root), inner instance IDs are PRESERVED at root.

  Strategy C — Part studio drawings (short partIds like "JHD", "RQzD"):
    Occurrence segments are partId values from the originating part studio.
    GET /api/v6/parts/d/{did}/w/{wid}/e/{psEid}?withThumbnails=false for each PS.
    Match segment === part.partId → use part.name.
    This happens when drawing views were created by selecting individual parts (not whole assembly).

  Strategy D — 3-seg unknown (seg[0] not in root, path length 3):
    seg[1] is a partId from an external/deleted element.
    Look in asmDef.subAssemblies[i].instances for inst.partId === seg[1] → inst.name.
    These are often PCB footprints/components from electronics sub-assemblies.

  Run strategies in order: A → B → C → D. Anything still unresolved → DROP (do not add to BOM).

  DELETED PARTS — DO NOT ADD TO BOM:
    If seg[0] is NOT in rootAssembly.instances AND seg[1] (for 4-seg paths) is also NOT in root,
    the part was completely deleted from the assembly (not just dissolved). The geometry cache is stale.
    These must be silently dropped — do NOT add an UNKNOWN row to the BOM.
    API confirmation: such instances are absent from asmDef.parts, asmDef.subAssemblies, and
    metadata/pi endpoint returns 404. The only fix is to delete and recreate the drawing view.
    Examples from harness_tray sheet: MY1xXDZ90YRQihB4m (hex nut M8) and MQXp8dBqbG5u4m7hL (hex nut M6)
    — both deleted from assembly, visible only as stale geometry. Correctly dropped from BOM.

  Sub-assembly instances resolve to the sub-asm name (not its leaf parts). E.g.:
  wheel_bracket_subassembly_1_2 — resolves via inst.name, but no partNumber (sub-asm has no partId).

  STALE IDs: Even after "Update Drawing", jsongeometry occurrence IDs may persist for deleted instances.
  UPDATE does NOT purge stale geometry paths. Only fix: delete and recreate the view.

STEP 4 — Get part numbers (for library/external parts):
  Assembly instance has: documentId, documentVersion, elementId, partId, isStandardContent.
  For same-doc parts:     GET /api/v6/parts/d/{did}/w/{wid}/e/{elementId}?withThumbnails=false
  For external-doc parts: GET /api/v6/parts/d/{inst.documentId}/v/{inst.documentVersion}/e/{inst.elementId}?withThumbnails=false
  Find part where part.partId === inst.partId → part.partNumber (may be null if not set), part.name.
  Standard library parts (isStandardContent:true) have partNumber set by default.
  partNumber takes priority; fall back to name if null.

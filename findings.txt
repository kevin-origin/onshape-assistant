Flat Pattern View (Drawing Creator)
-------------------------------------
- Flat body lookup: GET /api/documents/d/{did}/w/{wid}/insertables?includeFlattenedBodies=true&includeParts=false&elementId={psEid}
  → items[].isFlattenedBody=true, deterministicId=flat body ID, unflattenedPartDeterministicId=solid part ID
- Passing flat deterministicId as partId in onshapeCreateViews → silently ignored, no flat view appears
- Template auto-populates 4 standard views on draw create — explicit createViews call may be redundant
- CONFIRMED DEAD END: flat pattern views are NOT created via the REST API at all.
  Onshape's drawing editor runs in a cross-origin iframe (production-drawing-aps1*.onshape.com)
  and communicates with the backend via a proprietary WebSocket protocol called "Xe".
  The flat pattern view is triggered by the AutoCAD-style command `m_RunCmd: "^C^C_DRAWINGVIEW"`
  sent as a JSON XeData message over that WebSocket. No REST /modify call is ever made.
  Tested orientations tried (all silently ignored by REST): 'front', 'FLAT', 'FLAT_PATTERN'.
  Tested reference formats tried (all silently ignored): {partId: flatDeterministicId},
    {isFlatPattern:true, partId:solidId, flatBodyId:flatId}, {insertableQuery:...} (→ 400).
- CONFIRMED WORKING PATH (via chrome.scripting.executeScript into drawing iframe):
  Step 1: Focus canvas via CDP Input.dispatchMouseEvent (mousePressed+Released) at canvas center
           — CRITICAL: without canvas focus, RunCmd silently does nothing (Wt doesn't route command)
           — canvas coords: iframeRect.left + canvas.offsetLeft + canvas.width/2,
             iframeRect.top + canvas.offsetTop + canvas.height/2
  Step 2: chrome.scripting.executeScript(target:{tabId,frameIds:[drawFrameId]}, world:'MAIN')
           → window.getXeActiveDocument().RunCmd('^C^C_DRAWINGVIEW')
           — wait ~3s for COsDlgDrawingView to appear in DOM
  Step 3: chrome.scripting.executeScript(target:{tabId,frameIds:[0]}, world:'MAIN')
           → iframe.contentWindow.postMessage(msg, iframeOrigin)
    msg = {
      messageName: 'itemSelectedInSelectItemDialog',
      documentId, workspaceId, versionId: '',
      documentMicroversionId: <fb.microversionId from FRESH insertables call>,  ← CONFIRMED WORKS
      elementId: <psEid>, elementName, elementType: 'partstudio',
      elementMicroversionId: <same fb.microversionId>,
      elementConfiguration: 'default', itemType: 'part',
      partName: 'Flat pattern of <X>', idTag: <fb.deterministicId>,
      isFlattenedBody: true, context: '_OSDRAWINGVIEW',

    Effect: fires Wt.emit('partSelected') → XeData OsLoadStatistics → drawing enters placement mode
  Step 4: CDP Input.dispatchMouseEvent — move mouse to placement position, wait ~1s, then click
           sequence: mouseMoved → wait 1000ms → mousePressed → wait 100ms → mouseReleased

  Step 5: Cancel _PROJECTEDVIEW with RunCmd('^C^C') in drawing iframe
           — REST API confirms new view added: GET /api/v6/drawings/d/{did}/w/{wid}/e/{drawEid}/views

    (ALL flat bodies in same Part Studio share the same microversionId — it is the workspace microversion)

- world:'MAIN' is REQUIRED in chrome.scripting.executeScript — Xe/Wt globals only exist in MAIN world
- iframeOrigin for postMessage target: new URL(drawFrame.url).origin (varies per session/server)
- After placement, _PROJECTEDVIEW starts automatically — cancel with RunCmd('^C^C') or it will wait indefinitely

  → rows[].headerIdToValue keyed by header ID; material is nested object, use .displayName

Dimension textPosition coordinate system
----------------------------------------
- `textPosition` in an Onshape annotation requires a `viewId` field to be interpreted
  in view/model space (meters, same coordinate system as jsongeometry output).
  Without `viewId`, Onshape treats the coordinate as sheet space (mm from bottom-left
  of the sheet) — so a model-scale value like [0.3, 0.1, 0] appears at 0.3mm from the
  sheet edge, i.e. effectively the origin.
  Fix: always include `viewId: vid` in the textPosition object, same as edge references.

- Once viewId is set, textPosition coordinates are raw model meters matching jsongeometry.
  Text offset formula to get 5mm paper clearance outside the geometry:
    off = 5 * scaleDen / (scaleNum * 1000)   // paper_mm * (scaleDen/scaleNum) / 1000
  Height dim text (right of geometry):  [maxXval + off, midHval, 0]
  Width dim text (above geometry):       [midXval, maxHval + off, 0]
  No need to look up view.position — view-space coords are self-contained.

- chrome.runtime.reload() does not re-read files from disk for admin-console installed
  extensions. The extension reads from Chrome's internal profile copy, not the source
  directory. To deploy changes: publish a new version via publish.py.

Drawing auto-sync on release dialog (removed 2026-05-21)
---------------------------------------------------------
WHY REMOVED: Auto-syncing drawings updated document.modifiedAt, which caused the
export stale-revision check (check-releases handler) to always flag the doc as
having "changes since last release" — making export impossible right after releasing.

content.js — initDrawingsSyncOnRelease() IIFE
Watched for the release dialog appearing via MutationObserver, then fired a
fire-and-forget "sync-outdated-drawings" message to the background.

  const DIALOG_SEL = "div.modal.release-dialog.show, div.modal.workspace-permissions-dialog.show";
  let _triggered = false;

  const observer = new MutationObserver(() => {
    if (_killSwitchActive || _docDisabled) return;
    const dialog = document.querySelector(DIALOG_SEL);
    if (dialog && !_triggered) {
      _triggered = true;
      const docId = getDocIdFromUrl();
      const wid   = getWidFromUrl();
      if (!docId || !wid) return;
      chrome.runtime.sendMessage({ type: "sync-outdated-drawings", docId, wid });
    } else if (!dialog) {
      _triggered = false;
    }
  });

  observer.observe(document.body, { childList: true, subtree: true, attributes: true, attributeFilter: ["class"] });

background.js — "sync-outdated-drawings" message handler
Polled /api/documents/d/{docId}/w/{wid}/outofdatedelements in a loop (up to 10
passes, 1.5s delay between passes). Synced each out-of-date drawing via POST
syncApplicationElements. Used raw fetch (not onshapePost) because endpoint returns 204.

  } else if (msg.type === "sync-outdated-drawings") {
    (async () => {
      const { docId, wid } = msg;
      if (!docId || !wid) return;
      try {
        const xsrf = await getXsrfToken();
        for (let pass = 0; pass < 10; pass++) {
          const outdated = await onshapeFetch(`/api/documents/d/${docId}/w/${wid}/outofdatedelements`);
          const list = Array.isArray(outdated) ? outdated : (outdated?.items || []);
          if (list.length === 0) break;
          await Promise.all(list.map(el =>
            fetch(`${ONSHAPE_BASE}/api/documents/d/${docId}/w/${wid}/syncApplicationElements?applicationElementIds=${el.id}`, {
              method: "POST", credentials: "include",
              headers: { "Accept": "application/json", "Content-Type": "application/json", "X-XSRF-TOKEN": xsrf },
              body: "{}",
            })
          ));
          const recheck = await onshapeFetch(`/api/documents/d/${docId}/w/${wid}/outofdatedelements`);
          const remaining = Array.isArray(recheck) ? recheck : (recheck?.items || []);
          if (remaining.length === 0) break;
          await new Promise(r => setTimeout(r, 1500));
        }
      } catch (e) { console.log(`[DrawingSync] Error: ${e.message}`); }
    })();

API notes:
- GET  /api/documents/d/{did}/w/{wid}/outofdatedelements  → array of {id, name, ...}
- POST /api/documents/d/{did}/w/{wid}/syncApplicationElements?applicationElementIds={eid}
  Returns 204 (empty body) — must use raw fetch, not onshapePost; requires X-XSRF-TOKEN
- If re-adding: trigger AFTER release is confirmed (not on dialog open) to avoid
  the modifiedAt race with the stale-revision check.
